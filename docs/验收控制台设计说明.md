# 智能充电桩调度计费系统：验收控制台设计说明

> 版本：V1.0
> 状态：设计草案
> 日期：2026-05-20
> 目标：定义面向作业验收的特化功能，包括全局模拟时钟、验收样例自动执行、手动操作拦截、状态快照记录和原业务 UI 联动。

## 一、设计背景

作业验收用例以表格形式给出从 `06:00` 到 `11:00` 的事件序列，说明中采用 `1:10` 时间比例尺。若完全依赖人工按真实时间输入，容易出现输入时刻偏差，且无法高效复查每个动作前后的系统状态。

因此系统需要一个面向验收的控制台。它不是替代用户端或管理端的简化演示页，而是一个验收自动化执行中枢：

1. 统一控制全系统模拟时间
2. 支持载入并修正 xlsx 验收样例
3. 支持自动执行样例动作
4. 支持在原业务页面中手动操作，并按模拟时间延迟执行
5. 自动记录每个事件前后的真实系统状态快照
6. 将状态整理成验收表格可填写的结构

## 二、核心原则

### 2.1 全局模拟时间优先

启用验收模式后，系统所有业务动作必须以验收控制台的 `simulation_time` 为准，而不是以服务器或浏览器真实时间为准。

受影响的动作包括：

- 用户提交充电请求
- 用户修改充电模式
- 用户修改请求电量
- 用户取消排队
- 用户提前结束充电
- 管理员标记充电桩故障
- 管理员恢复充电桩
- 调度、计费、已充电量计算、当前费用计算

任何页面都不得在验收模式下绕过模拟时间直接使用真实当前时间。

### 2.2 自动执行，不是纯回放

载入 xlsx 样例后，主操作命名为“开始执行”，不命名为“开始回放”。

原因：

- “回放”容易被理解为仅展示预先算好的结果
- “执行”强调系统会自动操作真实业务流程
- 自动执行应等价于自动化测试脚本在用户端和管理端完成一系列真实操作

控制台可提供历史“回看快照”，但样例主流程应称为执行。

### 2.3 原业务 UI 必须真实参与

验收控制台不能替代原有用户端和管理端页面。

验收控制台负责：

- 控制模拟时间
- 管理样例事件
- 协调自动执行
- 拦截手动操作
- 记录状态快照
- 汇总表格视图

原业务页面负责：

- 用户端提交、修改、取消、提前结束
- 用户端当前任务、排队状态、详单展示
- 管理端设备状态、单桩队列、故障和恢复操作
- 管理端报表统计

验收时应能通过原业务 UI 观察真实系统状态，而不是只看控制台的简化结果。

### 2.4 手动操作必须可阻塞

若用户在验收模式下通过原业务页面手动操作，而时间条处于暂停状态，该操作不应立即提交后端。

正确行为：

1. 原业务页面捕获操作
2. 读取当前 `simulation_time`
3. 将操作登记为该时刻的待执行动作
4. 页面提示“已加入当前模拟时刻待执行队列”
5. 当时间条恢复，或用户点击“执行当前时间点”时，再按该模拟时刻真正调用后端接口

这样可以保证人工操作花费的真实时间不会影响验收样例中的业务时间。

### 2.5 xlsx 识别结果必须可修正

载入 xlsx 后，不应直接进入执行。必须先展示识别确认页。

确认页至少支持：

- 修改事件时间
- 修改事件类型
- 修改车辆编号
- 修改充电类型
- 修改充电量或故障持续分钟数
- 修改目标充电桩
- 启用或禁用某条事件
- 新增事件
- 删除事件
- 查看识别警告

例如验收表说明中可能写“30 条事件”，但实际 sheet 中可能识别出更多事件，此类差异必须显式提示。

## 三、事件模型

无论事件来自 xlsx 自动识别，还是来自原业务页面手动操作，进入验收控制台后都统一表示为验收事件。

### 3.1 事件字段

| 字段 | 含义 |
|------|------|
| `event_id` | 验收事件编号 |
| `source` | `XLSX` / `MANUAL` / `SYSTEM` |
| `at` | 模拟发生时间 |
| `type` | 事件类型 |
| `vehicle_code` | 车辆编号，如 `V1` |
| `station_code` | 充电桩编号，如 `FAST_01` |
| `charge_mode` | `FAST` / `SLOW` / `UNCHANGED` |
| `value` | 充电量、故障分钟数或特殊值 |
| `status` | `PENDING` / `EXECUTED` / `FAILED` / `SKIPPED` |
| `raw_text` | xlsx 原始事件文本 |
| `error_message` | 执行失败原因 |

### 3.2 事件类型

| 类型 | 含义 | 来源示例 |
|------|------|----------|
| `APPLY` | 提交充电请求 | `(A,V1,F,60)` |
| `CHANGE` | 修改充电请求 | `(C,V1,T,-1)` |
| `CANCEL_OR_STOP` | 取消排队或提前结束 | `(A,V2,O,0)` |
| `FAULT` | 充电桩故障 | `(B,F1,O,60)` |
| `RECOVER` | 充电桩恢复 | 由故障持续时间自动生成，或人工添加 |

### 3.3 编号映射

| xlsx 编号 | 系统编号 |
|----------|----------|
| `V1` | 验收用户 `V1`，可映射到测试账号 |
| `F1` | `FAST_01` |
| `F2` | `FAST_02` |
| `F3` | `FAST_03` |
| `T1` | `SLOW_01` |
| `T2` | `SLOW_02` |

车辆编号应贯穿用户端、管理端、状态快照和表格视图，便于与验收用例直接核对。

## 四、执行语义

### 4.1 时间条跳转

时间条跳转到指定模拟时间后，默认暂停。

推荐语义：

- 自动样例执行模式：跳转用于定位，必要时可重置并重放到目标时间
- 手动操作模式：跳转只定位模拟时间，不自动执行用户尚未布置的动作

当需要回退到历史时间点时，不做复杂撤销。推荐采用：

```
重置验收临时状态 -> 从起始时间重新执行事件 -> 执行到目标时间
```

### 4.2 执行当前时间点

点击“执行当前时间点”时：

1. 读取所有 `at == simulation_time` 且 `status == PENDING` 的事件
2. 按事件列表顺序执行
3. 每个事件执行前保存 `before_snapshot`
4. 每个事件执行后保存 `after_snapshot`
5. 刷新原业务 UI 可观察状态
6. 更新事件状态为 `EXECUTED` 或 `FAILED`

### 4.3 开始执行

点击“开始执行”后：

1. 模拟时间从当前值向前推进
2. 到达事件时间点时执行对应待执行事件
3. 若启用“逐事件暂停”，每个事件执行后自动暂停
4. 若启用连续执行，则自动推进到下一事件
5. 所有执行均通过真实业务接口或原业务页面操作队列完成

### 4.4 立即执行至最终态

“立即执行至最终态”用于快速验证正确性。

它不等待真实时间，而是：

1. 从当前或起始模拟时间开始
2. 顺序执行全部待执行事件
3. 自动处理由故障持续时间生成的恢复事件
4. 持续推进系统，直到所有可完成请求完成，或达到预设终止条件
5. 生成最终状态快照和详单汇总

## 五、验收控制台页面结构

验收控制台建议作为管理端页面：

```
/admin/acceptance
```

### 5.1 顶部全局状态条

展示：

- 验收模式是否启用
- 当前模拟时间
- 播放状态：暂停中 / 执行中 / 已完成
- 当前事件序号
- xlsx 样例名称
- 快捷入口：管理总览、设备控制、用户端任务、账单、报表

### 5.2 时间控制区

功能：

- 时间进度条
- 上一事件
- 下一事件
- 执行当前时间点
- 开始执行
- 暂停执行
- 继续执行
- 立即执行至最终态
- 重置执行
- 倍速控制

### 5.3 样例管理区

功能：

- 载入 xlsx
- 展示识别结果
- 修改事件
- 新增或删除事件
- 确认识别结果
- 保存修正后的事件列表

### 5.4 自动执行队列

展示：

- 全部验收事件
- 当前待执行事件
- 已执行事件
- 失败事件
- 事件来源
- 执行结果

### 5.5 当前状态总览

实时展示当前模拟时间下的系统状态：

- 快充桩 `FAST_01` / `FAST_02` / `FAST_03`
- 慢充桩 `SLOW_01` / `SLOW_02`
- 每个桩的运行状态、故障状态、队首车辆、排队车辆
- 每辆车已充电量
- 每辆车当前费用
- 等候区车辆列表
- 当前故障队列
- 最近调度结果

该区域用于辅助填写表格，但不应命名为“填表助手”。推荐命名为“当前状态总览”或“状态快照”。

### 5.6 快照历史

每个事件执行前后都保存快照，便于事后翻看和核对。

每条历史记录包含：

- 模拟时间
- 事件原文
- 执行前快照
- 执行后快照
- 变更摘要
- 请求编号和排队号
- 生成的详单
- 调度结果
- 异常信息

### 5.7 表格视图

表格视图根据状态快照生成，列结构对齐验收 xlsx：

| 时刻 | 事件 | 快充1 | 快充2 | 快充3 | 慢充1 | 慢充2 | 等候区 |
|------|------|-------|-------|-------|-------|-------|--------|

每个充电桩单元格展示：

- 车号
- 已充电量
- 当前费用
- 队列顺序

等候区单元格展示：

- 车辆编号
- 充电类型
- 请求电量
- 排队顺序

表格视图是状态快照的整理结果，不是独立伪造的验收结果。

## 六、原业务 UI 联动

### 6.1 用户端页面

用户端在验收模式下应显示轻量提示：

```
验收模式 · 当前模拟时间 07:10 · 暂停中
```

用户端操作应读取模拟时间：

- 提交请求时使用 `request_time = simulation_time`
- 修改请求时使用 `operation_time = simulation_time`
- 取消或提前结束时使用 `operation_time` / `stop_time = simulation_time`

若时间条暂停，操作进入待执行队列，不立即提交。

### 6.2 管理端页面

管理端设备控制页在验收模式下也应读取模拟时间：

- 故障操作使用 `fault_time = simulation_time`
- 恢复操作使用 `recover_time = simulation_time`
- 启停操作使用 `operation_time = simulation_time`

若时间条暂停，操作进入待执行队列，不立即提交。

### 6.3 页面刷新

事件执行后，应刷新或提示刷新相关原业务页面：

- 用户端当前任务
- 用户端账单
- 管理端设备控制
- 管理端总览
- 管理端报表统计

控制台可提供快捷跳转，但不替代这些页面的展示。

## 七、后端能力要求

为支撑验收控制台，后端需要补充或稳定以下能力：

1. 验收模式开关
2. 全局模拟时间存取
3. xlsx 事件解析
4. 识别结果修正保存
5. 验收事件队列
6. 事件执行器
7. 手动操作拦截队列
8. `replay_until` / `execute_until` 类能力
9. 状态快照生成
10. 快照历史查询
11. 表格视图数据生成
12. 故障持续时间自动生成恢复事件

现有批量模拟接口 `POST /api/test/batch-simulate` 可作为部分参考，但不能直接等同于验收控制台。验收控制台强调真实业务 UI 联动、模拟时间统一和事件前后快照。

## 八、快照数据口径

快照必须来自真实业务数据，不得由前端手写推断。

### 8.1 单桩快照

每个桩至少包含：

- `station_code`
- `charge_mode`
- `station_status`
- `current_vehicle_code`
- `queue`
- `charged_energy`
- `current_fee`
- `estimated_finish_time`
- `fault_remaining_seconds`

### 8.2 等候区快照

等候区至少包含：

- `vehicle_code`
- `request_id`
- `queue_number`
- `charge_mode`
- `request_energy`
- `waiting_order`

### 8.3 车辆费用快照

车辆费用必须按模拟时间计算：

- 已充电量
- 峰平谷电费
- 服务费
- 当前总费用

若车辆尚未开始充电，已充电量和当前费用为 `0`。

## 九、实施顺序建议

建议按以下顺序实现：

1. 定义验收事件模型和状态快照模型
2. 实现全局模拟时间与验收模式开关
3. 实现 xlsx 解析和识别确认
4. 实现事件队列与事件执行器
5. 实现状态快照和快照历史
6. 实现表格视图数据
7. 实现管理端验收控制台页面
8. 接入原用户端和管理端页面的模拟时间提示
9. 接入手动操作拦截队列
10. 用作业验收 xlsx 完整执行一遍并校验结果

## 十、非目标

以下内容不是验收控制台第一阶段目标：

1. 用控制台替代用户端或管理端真实页面
2. 为了展示而伪造桩状态或费用结果
3. 实现复杂的数据库级撤销系统
4. 将验收模式作为生产运营功能开放给普通用户
5. 将 `EXT_FULL_BATCH` 批量调度与验收样例自动执行混为同一概念
